# AI穿搭与衣橱规划师（国内秒哒版）

优先提升已有衣物利用率，再建议购买。每套方案说明真实单品、场合、天气和替换逻辑。

## 国内秒哒规则
- 本包只用于国内秒哒，界面、错误和交付均使用简体中文。
- 开放式分析与方案生成必须在生成应用时真实组合 wenxin-text-generation（展示名：文本生成大模型）；普通 @文字不构成能力绑定。
- 仅在需要账户、跨设备历史或协作时使用 Supabase，所有表和 Storage 按 user_id 开启 RLS。
- 生成应用不得依赖 Skill 包内脚本、shell 或本地绝对路径。
- 核心按钮必须调用真实能力并渲染真实结果，不得生成介绍页、静态表单或模拟数据。

## 核心能力
1. 建立场合、颜色、版型感受、尺码、预算和穿着限制档案。
2. 上传或手动添加单品，维护类别、颜色、材质、季节、正式度、洗护和可用状态。
3. 按天气、活动、正式度和舒适限制组合完整造型。
4. 生成周穿搭并处理重复、洗护和天气冲突。
5. 从已有衣物建立胶囊衣橱和组合矩阵。
6. 按行程、天气、活动和洗衣条件生成旅行打包。
7. 只有真实高频缺口才推荐购买，并说明至少三套兼容组合。
8. 用户需要图片识别或效果图时，再检索并组合真实国内图片Skill。

## 工作流
建立档案 → 录入衣橱 → 校对图片标签 → 选择场景/日期 → 生成方案 → 锁定/替换 → 周历或行李 → 缺口分析。

读取 references/wardrobe-contract.md、references/styling-rules.md 和 references/miaoda-app-spec.md。

## 严格优先级
- 只能引用用户已有且可用的单品，不虚构库存。
- 身形信息只用于舒适与表达偏好，不作羞辱性评价。
- 场合、天气、行动和舒适优先于潮流。
- 不强制身体照片，手动建档始终可用。
- 图片标签必须经用户确认，低置信度信息不能成为尺码或材质事实。
- 默认不接电商、支付或下单，不伪造库存与价格。
- 真实生成图片必须提供状态、预览、版本和下载。

## 必须交付
每张穿搭卡包含单品引用、场合、天气、理由、替换项、舒适提醒和缺失项；周历和旅行清单检查单品冲突及洗护状态。

## 常见坑
虚构衣物；把风格建议变成身材评价；每套都要求购物；只有效果图没有单品清单；上传图片无状态和删除入口。
