# 检查、修改并打包小红书小工具

请将当前工作区应用打包为**小红书小工具**。

## 工作流程
1. 读取src/下的项目代码，了解当前的项目结构，并根据一、检查中的要求，进行总结分析
#### 重点检查：
  * 项目结构、代码、配置和资源
  * 是否存在不支持的能力，包括数据库、网络 API 等
  * 构建及打包要求
  * 移动端适配和使用体验
2. 将总结分析中的改动，与用户同步，待用户确认后开始工作
### 汇总所有需要修改的问题，并明确告知用户：
  * 当前问题
  * 具体修改点
  * 是否影响现有功能、核心玩法或视觉风格
  修改方案必须以**最终通过小红书小工具校验**为目标，不提供可能无法通过校验的方案供用户选择。
  移动端适配问题也纳入代码变更确认流程，不单独输出适配结果。
**use `ask_user` tool 向用户确认后再执行后续流程。**

3. 读取 [guide.md](references/guide.md) 在task/目录下新建一个 xhs-项目名(英文名)的工作目录，生成打包需要的文件，禁止直接在原始的项目代码中进行修改
4. 读取 [guide.md](references/guide.md) 对task/目录下新建的工作目录进行打包，打包为一个zip
5. 根据 [guide.md](references/guide.md) 中关于zip 的限制进行校验，同时对zip 大小进行限制，不允许超过10M，当zip中出现图片导致超出zip 包大小时，需要对图片进行裁剪，请注意也是只对task/ 目录下的内容进行修改，最多尝试1次，如果无法压缩到10M以下，告诉用户进行修改

Remind
仅允许以下文件类型：jpg、css、gif、svg、png、js、jpeg、json、html、woff2、webp、woff。

## 输出

**📦 代码包**
> **改造点**：xxx
> **校验结果**：通过
> **产物路径**：`task/xxx.zip`

**只有最终校验通过并成功生成 ZIP 包后，才能输出产物路径。**
